# 原生符号链接修复与完整安装验证

修复 Windows 原生符号链接的两个问题：通过悬空链接创建文件会返回 `ENOENT`；删除指向目录的链接会错误检查目标类型，或因缺少目录打开标志返回 `EACCES`。修复后的固定 Release 通过 39 项原生测试、84 项客体检查，以及全新根目录中的完整 Node/npm 357 包安装。安装阶段 **299.500 秒**，180 秒目标仍未达到；历史严格有效最佳记录仍为 208.099 秒。

## 故障与修复

R23 共享目录身份候选在 `NativeSmallfileCreateProbe.py` 第 76 行失败。原冻结 R17 对照、关闭共享目录的候选以及另一根目录均复现。保留的最小客体样例创建了目标为 `missing` 的链接；宿主 `lstat` 确认重解析标签为 `0xA000000C`，客体 `readlink` 正常，而 `O_CREAT` 返回 `ENOENT`。此前测试为何未暴露此问题尚未证实，不能断言历史运行缺少符号链接权限。

路径解析器原先只读取托管 EA 链接目标。现在遇到重解析点时复用已有原生目标解码器，让悬空目标、相对目录链接和循环链接经过同一客体路径解析流程。普通目录快速路径保持原行为。R24 修复这一问题后通过 27 项原生测试，客体检查继续推进到清理阶段，暴露目录链接删除失败。

删除现在从不跟随链接的句柄读取类型，并通过同一个句柄执行 POSIX 删除。真正的目录仍拒绝 `unlink`，链接仍拒绝 `rmdir`，删除链接不删除其目标。测试覆盖存在及不存在的目录目标、循环链接、最终组件不跟随，以及目标内容保留。原生链接测试在缺少 Windows 链接权限时报告前置条件；本轮验收额外要求实际执行成功标记，未跳过该检查。工作区已有追踪调用得到保留，未提交其他会话的追踪和写回改动。
