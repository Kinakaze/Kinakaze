# WebUI 工作空间

WebUI 提供本机会话内的程序启动、进程查看与结束操作。以下功能需要从当前源码构建的 `init.exe`；v0.1.0 已发布的二进制仅包含旧版监控页。

## 打开工作空间

在完整运行目录（包含 `init.exe`、`worker.exe` 和已准备的 rootfs）中运行：

```powershell
.\init.exe --session-file .\session.json --web 127.0.0.1:0
```

打开终端中 `Kinakaze WebUI:` 后的地址。端口 `0` 自动选择可用端口；需要固定地址时可改为 `127.0.0.1:8080`。浏览器关闭不影响已运行的程序，init 退出会结束本会话中的所有 worker。会话文件应放在 rootfs 外。

自定义文件系统或原生模块目录时，附加 `--root C:/path/to/rootfs --dist C:/path/to/dist`。构建与运行环境见 [上手指南](getting-started.md)，默认发行文件系统见 [运行说明](runtime-release-v0.1.0.md)。

## 启动与管理程序

1. 等待“运行环境”显示“已就绪”，点击“启动程序”。也可点击“填入示例”，运行 `/bin/sleep 60`。
2. 程序路径使用 Linux 绝对路径，例如 `/bin/sleep`；每个启动参数分别添加，含空格的参数无需再加引号。表单不会隐式调用 shell。
3. 高级设置可填写工作目录和环境变量。变量每行一项 `NAME=VALUE`；留空使用默认环境，填写后替换客体环境列表。环境变量不持久保存到浏览器，提交成功后清空。
4. 提交成功表示运行环境接受了请求，不代表程序已成功完成装载。快速退出、缺少程序或依赖等错误请查看启动终端。程序输出与错误沿用 init 的标准输出、标准错误，当前没有浏览器终端或输出日志查看器。
5. 点击程序名查看 Linux PID、父进程、Windows PID、内存、CPU、执行代次和模块数量。程序路径来自最初的进程池启动请求；fork/exec 或其他入口创建的进程可能没有路径，此时显示“Linux 程序”。
6. “结束”需要在界面确认，会强制结束所选进程，不自动结束其子进程，也不提供优雅退出信号。待命环境由运行时维护，不提供结束按钮。

此入口适合后台、非交互程序，标准输入为 EOF。交互式 shell 请使用 `worker.exe run -- /bin/sh`。兼容性仍取决于客体程序及其依赖，WebUI 不会自动安装应用或补齐依赖。

## 状态与采样

- 概览不将待命 worker 计入运行应用。列表可按运行中、待命筛选，按程序路径、Linux PID 或 Windows PID 搜索，按内存或 CPU 排序。
- 工作集、私有提交内存来自 Windows 宿主。CPU 占用来自同一宿主实例连续两次累计 CPU 时间差，单核为 100%，多核可能超过 100%。首次连接、断线恢复、长时间暂停或采样不可用时显示 `—`，不以零伪装未知数据。
- 默认每 2 秒刷新，可选 5 秒或 10 秒，也可暂停后手动刷新。页面隐藏时停止自动采样；服务器不会在空闲时收集指标。
- 断线保留上次数据及更新时间，禁用启动和结束操作，并逐步降低重试频率。恢复连接后重新读取会话身份和操作凭据。
- 启动或结束请求的响应丢失时，界面会提示先刷新确认，**不会自动重发变更请求**。
- 操作记录仅保留当前页面的 20 条记录，刷新页面后清空。主题、插画显隐和刷新间隔保存在当前浏览器地址的本地存储中，不保存命令、参数或环境变量。
- 顶栏的“插画”可收起角色区域，“帮助”可查看启动、输出与采样说明。[视觉方向与素材记录](webui-visual-design.md) 记录了本轮 ACG 改版的参考与原创素材。

通过 `worker run --web ...` 开启且没有预热池的会话显示“监控模式”，可以查看和结束进程，但不能在其中启动新程序；使用上述独立 init 会话开启完整入口。

## 本机访问边界

服务只绑定 `127.0.0.1`，校验包含端口的 Host。变更接口还要求同源 Origin、当前 WebUI 的随机令牌及 JSON 内容类型；不开放 CORS，不接受分块请求或超过 16 KiB 的请求体。该令牌与运行时、命令行会话凭据分开。结束操作同时匹配 Linux PID、执行代次、Windows PID 和完整创建时间，并使用固定的内核进程句柄执行，过期身份会被拒绝。

WebUI 是当前本机用户的操作入口，并非多用户鉴权或隔离边界。不要通过反向代理、端口转发等方式对外开放。

## 回归验证

Rust 单元测试覆盖来源校验、请求大小、参数校验、失效进程身份和实际 HTTP 收发。浏览器回归需要 Python Playwright 与 Chromium，并使用真实 runtime 启动客体程序：

```powershell
python tools/test-webui.py --init path/to/new/init.exe --dist artifacts/kinakaze-dist
```

脚本在临时目录中启动独立会话，验证图形化启动、参数边界、cwd/环境变量、进程结束、筛选排序、断线恢复、主题、键盘焦点和 390px 移动布局；退出时回收会话。报告、桌面/移动截图及会话输出位于 `artifacts/webui-validation/`，不加入源码仓库。
