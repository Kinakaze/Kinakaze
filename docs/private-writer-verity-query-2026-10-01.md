# 私有写入句柄的实时 verity 检查

普通文件的原生写入打开现在复用尚未公开的独立句柄查询 verity EA，省去一次重复原生打开。该句柄已经具有查询权限并持有 native write access；新 verity enable 的 deny-write reservation 继续排除并发发布。每次打开仍读取实时 EA，未引入跨操作的元数据缓存。

已有公开或共享描述符继续通过独立查询句柄检查。ENABLED 仍返回 EPERM，损坏记录仍返回 EIO；PREPARING/BUILT 仍获取 inode 锁、重新查询并执行原有持久化恢复。恢复使用同一个原生 inode，保留重命名、替换和删除后的身份。所选路径没有新增生产开关。

## 验证与范围

候选通过 112 项原生回归，另有 3 项已声明忽略的辅助测试/基准；普通、transfer、pooled 三种模式共 57 项客户机检查全部通过。新回归覆盖实时无记录查询、PREPARING 恢复、原名称替换、原 inode 删除后继续检查、损坏记录和 ENABLED 拒绝。现有回归覆盖 verity 事务、权限、只读挂载、保留目录描述符、fork/exec 和复制描述符。

这些对照二进制尚不包含后续 main 的文件向量 I/O、普通非排他创建和 v1.2.0 集成改动。此报告不宣称整套安装达到 180 秒；严格口径的既有最佳完整安装仍为 [208.099 秒](selected-routes-full-install-2026-10-01.md)。完整安装需使用新的冻结集成构建另行验证。
