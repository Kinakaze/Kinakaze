# Kinakaze v0.7.0

在 Windows x86-64 上直接运行 Linux x86-64 程序的用户态兼容层。

本版本修复可能导致 MySQL 关机挂起的条件变量丢失通知问题，完善 SysV 共享内存查询与生命周期，并降低混合 TCP/PTY 等待的空闲轮询。

## 主要变化

- Oracle MySQL 8.4.11 的初始化、事务提交/回滚、并发写入、正常关机、重启和 SIGKILL 后恢复重复测试通过。
- `/proc/sysvipc/shm` 返回真实共享段信息；支持私有段枚举、跨进程挂接计数、延迟删除和键复用，ipcs/lsipc 可查询已创建的段。
- PTY 就绪事件进入 poll/epoll 的混合等待，补充终端数据、挂断和重置测试。
- 原始 `mincore` syscall 接入真实驻留查询，验证错误码、输出边界与映射空洞。
- 固定 Debian 清单完整功能复测：465/758 通过，覆盖率 61.35%；59 失败、2 超时、232 未测试。
- Python、Nginx、Redis、PostgreSQL、MariaDB、SQLite 多进程、FFmpeg、Java 回归通过。

## 使用

下载 `Kinakaze-0.7.0-windows-x86_64.zip`，解压到新目录后运行 `init.exe`。首次启动联网准备 Debian bookworm 环境，宿主无需安装 Python。升级前退出旧环境。

要求 Windows 11 24H2 或 Windows Server 2025 及以上、x86-64。源码构建使用 Rust 1.95.0、MSVC、LLVM 和 Python 3.13；发布工作流另行执行构建、单元测试和发行包首次运行验证。

## 已知限制

兼容性仅代表已测试范围，尚未实现完整 Linux ABI，也不是安全隔离边界。Debian 99% 命令覆盖目标尚未完成，NUMA、内核设备等能力仍有缺口。没有同机原生 Linux 性能对照，不宣称性能已比肩 native。

详细证据见仓库 `docs/compatibility-goal-2026-09-29.md` 和 `docs/server-performance-2026-09-29.md`。
