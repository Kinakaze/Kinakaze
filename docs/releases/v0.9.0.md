# Kinakaze v0.9.0

在 Windows x86-64 上直接运行 Linux x86-64 程序的用户态兼容层。

本版本集中修复 Bun/Node 编程 agent 的运行、信号和内存管理问题，并扩展原始 syscall、调试和映射支持。

## 主要变化

- 修复嵌套信号、条件变量等待、ELF 私有映射上的 futex、终端 ioctl 与 proc 描述符路径，补充 dsh、OpenCode、zcode、Codex、Claude 和 pi 的功能回归工具。
- `msync` 接受有效的堆、栈和 ELF 映射；`MADV_DONTNEED` 丢弃整段匿名映射时不再写入所有稀疏页。大型匿名分配遵守 Windows Job 内存提交限制，失败返回 `ENOMEM`，允许 Bun 分配器回退。
- 增加私有匿名 `mremap`、`semtimedop` 和基于 Windows 调试事件的 `ptrace` 路径，修正 `memfd_create` 的匿名文件生命周期及部分原始 syscall 分派。
- 改进 AOT 间接调用目标发现并更新缓存格式；trap 查询使用固定容量缓存，补充回收、并发与内存资源回归。

## 使用

下载 `Kinakaze-0.9.0-windows-x86_64.zip`，解压到新目录后运行 `init.exe`。首次启动联网准备 Debian bookworm 环境，宿主无需 Python。升级前退出旧环境。

要求 Windows 11 24H2 或 Windows Server 2025 及以上、x86-64。源码构建使用 Rust 1.95.0、MSVC、LLVM 和 Python 3.13；发布工作流执行构建、单元测试、首次安装和 ZIP 解压运行验证。提供运行包、源码 ZIP 及各自的 SHA-256 文件。

## 验证范围与限制

Agent 修复阶段的六种 CLI 共完成 94 项本地确定性接口场景；内存回归检查匿名页丢弃、分配失败、句柄及线程稳定性和子进程清理。详细环境、安装布局要求与逐项证据见 [运行时修复记录](../agent-runtime-fixes-2026-09-30.md)。这些记录不代表在线模型服务验证或长期无泄漏证明。OpenCode 测试使用 24 GiB Job 内存上限，实际峰值明显高于 dsh。

`ptrace` 尚不支持 fork/exec 事件选项；共享或文件映射的 `mremap` 返回不支持。兼容性以实际测试范围为准，未实现完整 Linux ABI，没有同机原生 Linux 性能对照。
