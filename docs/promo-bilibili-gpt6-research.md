## 实际工具如何分工

这些案例展示的可借鉴流程是：参考素材 → 分镜与镜头规格 → 可编辑场景 → 动画预演 → 正式渲染 → 文字、声音与剪辑合成 → 成片复查。

- **GPT-6 / Codex**：承担任务拆解、脚本编写、工具调用与检查。GPT-6 Astra 的官方 API 模型页列出文本输出及工具能力，原生视频模态标为不支持；视频成品通过制作工具生成。[OpenAI Docs](https://developers.openai.com/api/docs/models/gpt-6-astra)
- **Blender 与 MCP / Python**：构建可编辑三维场景，处理对象、材质和镜头。案例提及的社区 MCP 项目支持场景检查、对象与材质操作、Python 执行；它是第三方集成。[MCP for Blender 项目](https://github.com/ahujasid/mcp-for-blender)
- **Remotion**：组织程序化视频的文字、媒体和时间线；官方提供适用于 Codex 等编程代理的技能，以及 Three.js 集成和转场组件。[官方技能](https://www.remotion.dev/docs/ai/skills)、[Three.js 集成](https://www.remotion.dev/docs/three)、[转场文档](https://www.remotion.dev/docs/transitioning)

工具选择服务于镜头。现有 Three.js 工程仍可复用；是否改用 Blender，应由场景、材质和渲染需求决定。

## 对 Kinakaze 下一版的具体建议

以下为本次调研后的创作建议，尚未实施或渲染。

1. **先做一段 12–15 秒的质量样片。** 确定主材质、灯光、字体与运动曲线，并用连续镜头验证效果，再扩展全片。
2. **让生长效果承担叙事。** 光标移动时牵出路径，路径抵达处长出工具结构，文件沿路径进入 Agent，再回到真实文件内容。每个动作都对应产品能力。
3. **用景别与空间关系制造变化。** 微距进入、侧向跟拍、环绕揭示与全景收束交替使用；上一镜的主体或前景形状引导下一镜，不把所有内容固定在同一种构图里。
4. **按音乐乐句安排动作。** 重拍用来完成关键形变或揭晓，其他时间保留减速、停顿和旁白空间。字幕阅读时间与剪辑节奏一起设计。
5. **三维主体与实录互相接续。** 文件表面转入 vi/vim 编辑，连接结构引出 SSH，窗口展开接到 GNOME，体素结构引出 Minecraft 实际运行画面。实录必须保留其真实能力边界。
6. **逐镜打磨而非只检查导出。** 检查边缘倒角、粗糙度、明暗层次、反射、运动模糊、中文排版、对象穿插和转场落点；分别检查有声和静音播放。

建议制作路线：Blender 负责需要精细材质和空间运镜的主镜头，Remotion 或现有合成工具负责文字、真实操作录像、选定的 A 女声与音乐。继续采用雾白、冰蓝、明亮轻电子方向。

本次只完成调研与记录，没有安装插件、修改全局配置或重渲染现有成片。
